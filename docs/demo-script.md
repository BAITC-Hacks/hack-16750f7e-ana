# Сценарий защиты A^2SCEND

## Подготовка

Из корня: `cd career-quest`, затем `python server.py` (или `python3 server.py`). Открыть http://127.0.0.1:8000. Использовать случайные пароли employee/hr из терминала. Для воспроизводимого демо оставить CQ_STORAGE_PATH незаданным или сначала выполнить HR → «Сбросить». Не сбрасывать рабочий набор без намерения его заменить.

Все данные этого сценария синтетические. E0028 создан генератором fixture; в production-формуле нет ветки выбора по этому ID. Внешний AI по умолчанию выключен.

## Основной сценарий, около пяти минут

1. Войти как **employee**. Показать E0028: Backend Engineer, Middle → Senior, покрытие требований 70,8%. Имя в интерфейсе — из профиля, не из отдельной карточки демо.
2. В карте навыков показать System Design: 2 из 4; Public Speaking: 1 из 3. Минимальный уровень не определяет рекомендацию автоматически.
3. В главной карточке открыть **«Почему этот шаг»**. На исходном наборе первым идёт System Design. Показать четыре фактора и веса; история Public Speaking снижает соответствие формата. Пропуски не доказывают отсутствие мотивации.
4. Показать источник **«Алгоритмический режим»**. Если отдельно настроен API, дождаться результата: либо Hybrid AI, либо явный резервный режим с причиной. Не обещать, что LLM обязательно изменит порядок.
5. Нажать **«Смоделировать»** на System Design: прогноз 70,8% → 77,1%, +6,3 п.п., 6 часов. Профиль и XP ещё не меняются. В планировщике выбрать 16 часов и две активности (System Design, затем Public Speaking): 11 часов, последовательный прогноз 70,8% → 77,1% → 85,4%. При бюджете 2 часа подходящих вариантов для этого профиля нет.
6. Вернуть бюджет 8 часов и нажать **«Отметить выполненным»** на System Design. Навык становится 3, покрытие 77,1%, добавляется 100 XP, шаг исчезает из рекомендаций. Новый следующий шаг рассчитан по изменившемуся профилю.
7. Показать историю, XP и добровольную паузу в нижней части страницы. Пауза сохраняет достигнутое; участие не обязательно. Повторный HTTP complete для уже выполненного ID идемпотентен: дополнительных XP/gain нет.
8. Выйти и войти как **hr**. Показать суммарные разрывы уровней, причины отсутствия шага, качество требований и участие по активностям. Объяснить разницу между записями истории и уникальными участниками. HR не может завершить активность за сотрудника.
9. **«Загрузить датасет»** → выбрать sample_upload/employees.json и sample_upload/activity_history.csv → **«Дополнить / обновить»**. Показать предпросмотр и предупреждение о смешении с демо. Применить. Найти JURY01 через выбор профиля. Для проверки ошибки выбрать повреждённый JSON: кнопка применения останется недоступной, данные не изменятся.

## Техническое подтверждение

Из папки приложения:

```bash
python -m unittest discover -s tests -v
python evaluation.py
python benchmark.py
python ai_smoke_test.py --live
```

Live smoke без полной конфигурации печатает SKIPPED; это не PASS. В проверенной среде: **Реальная AI-интеграция не проверена**. Официальный starter kit также не получен; sample_upload — синтетические fixtures.

Для демонстрации сохранения задайте CQ_STORAGE_PATH=./progress.sqlite перед стартом, выполните шаг, остановите сервер и запустите снова с тем же путём. Gains не применяются повторно; навыки/история/XP восстанавливаются. Пароли при отсутствии явных переменных будут новыми — используйте новый вывод терминала.

На защите отличайте рабочую механику и проверки ограничений от доказательства пользы: рост вовлечённости и качество LLM ещё требуют добровольного пилота и экспертной оценки.
