# Интеграция A^2SCEND: отчёт

Дата проверки: 23.09.2026. Основное приложение: `career-quest/`. Дополнительное: `fuse/career-quest/`. AGENTS.md в репозитории и непосредственной родительской папке не найден. Оба приложения используют Python stdlib, http.server и vanilla UI; переход на другой стек не потребовался.

## Исходное состояние

До изменений уже были модифицированные исходники, неотслеживаемые AI/import/evaluation-файлы и скопированные security.py, SECURITY.md, .env.example, tests/test_security_integration.py; папка fuse также была неотслеживаемой. Архив career-quest.zip был удалён **до** работы: его не восстанавливали. Git reset/clean, изменения remote, commit и push не выполнялись. fuse сохранён без редактирования, .git из него не переносился.

Команда `python -m unittest discover -s tests -v` в основной папке не запустилась: Windows Store alias вернул «Доступ к этому файлу из системы отсутствует». Доступный интерпретатор: Python **3.13.14**, Windows, `C:/Users/user/AppData/Local/Programs/pgAdmin 4/python/python.exe`.

Фактически выполненная замена из `career-quest/`:

```powershell
& 'C:/Users/user/AppData/Local/Programs/pgAdmin 4/python/python.exe' -c "import sys,runpy; sys.path.insert(0,'.'); sys.argv=['unittest','discover','-s','tests','-v']; runpy.run_module('unittest',run_name='__main__')"
```

Для evaluation/benchmark/smoke использовался тот же runtime и `runpy.run_path('имя.py',run_name='__main__')`. Изолированный sys.path этой поставки требует явного добавления текущей папки. Обычный Python так настраивать не требуется.

**Baseline:** 54 выполненных теста прошли; дополнительно `setUpClass` security-набора завершился ошибкой `server.build_server` отсутствует. Итого baseline был **FAILED (errors=1)**, а не полностью зелёным. Эти тесты были скопированы из fuse и обращались к другому AuthManager/API. Evaluation отдельно: 12 сценариев, 12 PASS, 0 нарушений. Benchmark отдельно: профиль max 0,0031 с, HR 0,2905 с, искусственный AI deadline 8,0145 с, offline calls 0.

## Почему изменены скопированные security-тесты

Сохранены проверки анонимного доступа, изоляции employee, read-only HR, CSRF/Origin, cookie/headers, закрытых файлов, парсинга загрузки, атомарности, минимизации полей, throttling, ротации сессии и аудита. Изменения ожиданий связаны с контрактом основного приложения:

- `/api/session`, верхнеуровневое `csrf`, AuthStore вместо `/api/me`, `user.csrf_token`, AuthManager.
- `/api/employees` запрещён сотруднику (403), а не отдаёт каталог даже с одним элементом.
- Повторный complete возвращает 200 с прежними XP/историей, а не 422: требование основного проекта — идемпотентность.
- Ошибки валидации — 400, не 422; неизвестный API без сессии — 401, а не публичный 404.
- Частичная настройка паролей допустима: для ненастроенной роли создаётся случайный пароль; фиксированные пароли fuse не включаются.
- Замена только каталога проверяется через явный mode=replace: все четыре раздела обязательны. Legacy-вызовы сохранены ради существующего тестируемого поведения.

Проверки 29 исходных тестов и расширенного набора из 54 сохранены. В тесте сетевого AI-контракта ответ mock использует wire-псевдонимы, а результат проверяется по локальным ID: это соответствует усиленной границе приватности.

## Подтверждённые исправления и добавления

- Бизнес-валидация AI отделена от проверки JSON; проверяются актуальная доступность, положительный gap-effect, бюджет и существование факторов.
- Wire-контекст не содержит импортированных свободных строк. Тест проверяет реальное тело Request с персональными маркерами в названиях и ID. Псевдонимы маппятся обратно локально.
- Сравнение альтернатив в UI строится из локальных длительностей, дельт и факторов. Свободный текст LLM не объявляется проверенным фактом.
- Кеш учитывает время и ревизию. UI отвергает старый запрос при смене бюджета/профиля/роли; backend проверяет свежесть после сети.
- Импорт использует один парсер и движок для preview и commit; commit защищён ревизией. В режиме merge история сохраняется; replace требует полный набор.
- SQLite сохраняет профили, каталог, требования, историю и паузу согласованно; исключение записи откатывает память. Соединения закрываются явно, включая Windows.
- Случайные пароли, employee/HR, CSRF и изоляция сохранены. Ротация сессий и отказ после пятой ошибки усилены.
- Новый UI использует только основное API; импортированный HTML остаётся текстом.

Окружение: Windows, Python 3.13.14, локальный CPU, синтетические 200 профилей / 12 навыков / 12 активностей. Время не является production SLA.

|---|---|---|

| evaluation.py | 12/12 бизнес-сценариев, 0 нарушений | VERIFIED |
| benchmark.py, employee_view | максимум 0,0073 с среди 10 вызовов Python-функции | VERIFIED |
| benchmark.py, hr_view | 0,3405 с, один вызов для 200 сотрудников | VERIFIED |

Реальная AI-интеграция не проверена. Успешные mock-тесты доказывают локальный контракт и ограничения, но не доступность выбранной модели, качество её выбора или бизнес-эффект.

Браузер: реальный локальный Chrome, изолированный профиль, временный сервер на свободном порту, синтетический memory-engine и выключенный внешний AI. Основной flow вход → профиль → объяснение → симуляция → complete → пересчёт → HR → импорт прошёл на **1440×900, 1366×768, 390×844**. На этих экранах отсутствовал горизонтальный скролл страницы; необработанных JS-ошибок (error/unhandledrejection) — 0. Скриншоты login/profile/explanation/simulation/hr/import и машиночитаемый report.json находятся в игнорируемой папке `career-quest/browser-artifacts/`. Изображения просмотрены визуально.

В песочнице Chrome/Edge аварийно завершали GPU-процесс (access denied); разрешённый запуск за её пределами позволил выполнить проверки. Это ограничение среды тестирования, не обход авторизации приложения. Браузерный тест также проверяет focus trap/return, ошибку импорта, отсутствие выполнения импортированного HTML и поздний AI-ответ при смене бюджета.
