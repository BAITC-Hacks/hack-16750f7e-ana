# Career Quest — объяснимый навигатор развития сотрудника

Локальный MVP для кейса Halyk Bank на HackAlem AI. Career Quest помогает сотруднику выбрать следующий шаг развития, понять его пользу и увидеть изменение прогресса. HR получает картину дефицита компетенций и приватный список сотрудников, которым можно предложить поддержку.

## 1. Проблема и аудитория

Каталог курсов не отвечает на вопросы: «Что полезнее именно мне?», «Почему сейчас?» и «Сколько времени потребуется?». Career Quest связывает профиль, требования следующего грейда, историю участия и доступные активности.

Основной пользователь — сотрудник со стажем 1–5 лет. Второй — HR, который помогает команде развиваться. Это инструмент добровольного развития, а не автоматическая система кадровых решений.

## 2. Что реализовано

| Возможность | Реализация |
|---|---|
| Две роли | Вход сотрудника и HR; сервер проверяет роль и право доступа к профилю |
| Личная траектория | Грейды, уровни навыков, пробелы и процент готовности |
| Рекомендации | До трёх шагов с объяснением требований, эффекта, истории и нагрузки |
| Практический наставник | Упражнения по навыкам, проверяемый результат и следующая активность |
| Дополнительный AI-совет | OpenAI Responses API при явном включении интеграции |
| **План под бюджет времени** | Подбор доступных по времени шагов с объяснением изменения первого варианта |
| **Лаборатория «что если?»** | Симуляция 1–3 шагов: последовательный прирост готовности, изменения навыков и полностью закрытые пробелы |
| Прогресс и награды | 100 XP за уникальную завершённую активность, уровни, значки и добровольная недельная цель |
| Добровольная пауза | XP сохраняется; выполнение временно блокируется, участник исключается из HR-списка поддержки |
| HR-аналитика | Пробелы компетенций, участие, завершённость, число пауз и приватный список поддержки |
| Импорт | Загрузка профилей, справочников и истории из JSON/CSV через HR-интерфейс |

### Что отличает демонстрацию

- **Выбор с учётом нагрузки.** Лучший по рейтингу шаг может не помещаться в доступное время. Интерфейс объясняет компромисс и отсутствие подходящих вариантов.
- **Проверка до действия.** Симуляция не начисляет XP и не меняет историю. Она доступна и во время паузы.
- **Без двойного счёта.** Эффект цепочки пересчитывается после каждого шага с учётом уровней и ограничений каталога; независимые прогнозы не складываются механически.
- **Объяснимость вместо обещания повышения.** Готовность рассчитывается локально по требованиям, а внешняя AI-модель не управляет оценками.

## 3. Как работает решение

1. Сервер формирует синтетический набор; HR может дополнить его через импорт.
2. Сотрудник входит и видит свой профиль. HR получает сводку и доступ к просмотру профилей.
3. Движок определяет следующий грейд, его требования и текущие пробелы.
4. Завершённые и неподходящие по роли активности исключаются; остальные оцениваются по четырём факторам.
5. Сотрудник читает объяснение, выбирает бюджет времени и при желании моделирует цепочку шагов.
6. После выполнения отмечает активность завершённой. Пересчитываются навыки, готовность, XP и рекомендации.
7. HR видит обновлённые данные, но не может выполнять активности за сотрудника.

### Расчёт прогресса

```text
score = 100 × (0,46 × соответствие грейду
             + 0,26 × влияние на готовность
             + 0,18 × соответствие истории участия
             + 0,10 × выполнимость по длительности)

готовность = среднее по требуемым навыкам(
    min(текущий уровень / требуемый уровень, 1)
) × 100%
```

Компоненты score нормированы; итог округляется до одного знака. История похожих форматов и повторные пропуски влияют на приоритет. Реализация находится в [engine.py](career-quest/engine.py).

Завершение применяет `gain` с пределом `max_level`, не снижая достигнутый уровень. Повторное завершение не даёт повторный прирост. Каждые 300 XP открывают уровень, значки выдаются за 1, 3 и 5 уникальных активностей. Недельная цель — две активности с понедельника по текущую дату сервера, без штрафов.

**Готовность и XP — разные показатели.** Готовность не является вероятностью повышения, а симуляция не доказывает фактический рост компетенции.

## 4. Технологии

| Слой | Используется |
|---|---|
| Backend | Python 3.10+, стандартная библиотека: `http.server`, `json`, `csv`, `threading`, `urllib` |
| Frontend | HTML, CSS, JavaScript, Fetch API; без фреймворка и сборщика |
| Хранение | Объекты в памяти процесса, входные файлы JSON/CSV |
| Вход | PBKDF2-HMAC-SHA256, индивидуальные соли, серверные сессии, cookie, CSRF-токен |
| Рекомендации | Детерминированный алгоритм; обученной ML-модели в репозитории нет |
| AI | Опциональный OpenAI Responses API; модель задаётся через `OPENAI_MODEL`, фиксированной модели по умолчанию нет |
| Тесты | `unittest`, HTTP-тесты локального сервера, mock внешнего AI |

Для основного сценария интернет, API-ключи, база данных и установка пакетов не нужны.

## 5. Архитектура

```text
Браузер: index.html + styles.css + app.js
                 │ JSON / HTTP, cookie, CSRF
                 ▼
server.py — маршруты, проверка роли и владельца профиля
       ├── auth.py — пароли, сессии, лимит попыток входа
       ├── engine.py — данные, ранжирование, симуляции, XP, HR-сводка
       └── coaching.py — локальные упражнения
                    └── OpenAI API (при явном включении)

HR → JSON/CSV → импорт → данные в памяти → пересчёт
```

Исходники находятся в [career-quest/](career-quest/), тесты — в [career-quest/tests/](career-quest/tests/). Архив `career-quest.zip` также есть в репозитории, но эта инструкция относится к исходникам каталога, а не к архиву.

## 6. Установка и запуск

1. Установите Python 3.10+ и скачайте либо клонируйте репозиторий.
2. Из корня репозитория выполните:

   ```bash
   cd career-quest
   python3 server.py
   ```

   На Windows, если интерпретатор доступен как `python`, используйте `python server.py`.

3. Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000).
4. Возьмите логины и пароли **из текущего терминала сервера**: строки `Local login: employee / …` и `Local login: hr / …`. При каждом запуске без заданных паролей генерируются новые.

`employee` привязан к E0028 — Аян Серик, Backend Engineer, Middle, стаж 52 месяца. `hr` открывает HR-сводку. Другой порт: `python3 server.py --port 8080`.

**После изменения Python-кода остановите сервер через Ctrl+C и запустите снова.** Если порт занят, остановите предыдущий процесс или выберите другой порт. Сервер запрещает совместное использование порта. Перезапуск сбрасывает данные демо и сессии.

### Настройки окружения

| Переменная | Назначение |
|---|---|
| `CQ_EMPLOYEE_PASSWORD`, `CQ_HR_PASSWORD` | Постоянные пароли локальных учётных записей |
| `CQ_EMPLOYEE_ID` | Привязка сотрудника к ID встроенного профиля; по умолчанию E0028 |
| `PORT` | Порт, по умолчанию 8000; аргумент `--port` имеет приоритет |
| `CQ_SECURE_COOKIE=1` | Флаг Secure для cookie при развёртывании за HTTPS |
| `CQ_QUIET=1` | Отключение HTTP-логов |

### Опциональные внешние AI-советы

По умолчанию данные внешней модели не отправляются. Если организация разрешила интеграцию, задайте в PowerShell перед запуском:

```powershell
$env:OPENAI_API_KEY = "ваш-ключ"
$env:OPENAI_MODEL = "доступный-вам-id-модели"
$env:CQ_ALLOW_EXTERNAL_AI = "1"
python server.py
```

На Linux/macOS те же переменные задаются командой `export ИМЯ="значение"`. Одного ключа недостаточно: требуется `CQ_ALLOW_EXTERNAL_AI=1`. При ошибке, неполном ответе или таймауте AI остаётся локальный практический план.

## 7. Как проверить решение жюри

Используйте свежий демо-набор. При необходимости войдите как HR и нажмите «Сбросить».

1. **Войдите как `employee`.** Откроется E0028 с готовностью **70,8%** к Senior.
2. **Посмотрите первый шаг.** Рекомендуется System Design, хотя публичные выступления — более слабый навык. Нажмите «Почему этот шаг»: доступны четыре фактора и формула.
3. **Измените бюджет лаборатории.** При 8 часах доступен System Design (6 часов). При 5 часах первым доступным вариантом становится публичное выступление; интерфейс объясняет разницу. При 2 часах подходящих активностей нет.
4. **Проверьте «что если».** Выберите 16 часов, затем System Design и публичное выступление. Сценарий занимает **11 часов**: **70,8% → 77,1% → 85,4%**. Навыки и XP в профиле пока не меняются.
5. **Отметьте System Design выполненным** в рекомендациях. Навык изменится с 2 до 3, готовность — до **77,1%**, начислится **100 XP**. Повторная награда за тот же шаг невозможна.
6. **Возьмите паузу.** Прогресс сохранится, выполнение временно недоступно. Симуляция остаётся доступной. Затем возобновите участие.
7. **Выйдите и войдите как `hr`.** Проверьте компетенции, участие и приватный список поддержки. HR просматривает профили, но не выполняет активности за сотрудников.
8. **Проверьте импорт.** Загрузите [employees.json](career-quest/sample_upload/employees.json) и [activity_history.csv](career-quest/sample_upload/activity_history.csv). В разделе профилей выберите JURY01 и проверьте его рекомендации.

Числа воспроизводятся для встроенного E0028 до импорта и выполнения активностей. Это расчёт демонстрационного набора, а не результат исследования эффективности программы.

### Автоматические проверки

Из каталога `career-quest`:

```bash
python3 -m unittest discover -s tests -v
```

Проверяются рекомендации, прогресс, повторные и параллельные завершения, XP, AI-fallback, роли, подмена ID, CSRF, сессии, закрытые файлы, добровольная пауза, занятый порт, бюджет времени и симуляция без изменения данных. AI-запросы подменяются; реальная модель в тестах не вызывается.

## 8. Данные и интеграции

- Встроено **200 синтетических сотрудников**, четыре профессиональные роли, **12 навыков** и **12 активностей**. Генераторы и история находятся в `engine.py`.
- Профиль содержит `employee_id`, `name`, `role`, `grade`, `tenure_months`, `skills`. Активность использует `event_id`, `audience.roles`, `skills` с `gain` и `max_level`, `duration_hours`.
- CSV-история содержит `employee_id,event_id,status,on_time,date`. Примеры находятся в `sample_upload`.
- Импорт объединяет профили по ID; непустые загруженные справочники заменяют соответствующие справочники. История заменяется для указанных в ней сотрудников. Пустой список истории не очищает существующие записи.
- LMS, HRIS, корпоративное SSO и реальные кадровые базы **не подключены**.
- При включённом AI в OpenAI передаются роль, целевой грейд, навыки и практический план, без имени, ID сотрудника и исходной истории; используется `store: false`. Это всё равно передача данных внешнему сервису, а не полностью внутренний контур.

### API

| Маршрут | Доступ / назначение |
|---|---|
| `GET /api/health` | Без входа: состояние сервера |
| `POST /api/login` | Логин и пароль → cookie сессии и CSRF-токен |
| `GET /api/session`, `POST /api/logout` | Текущая сессия / выход |
| `GET /api/employee?id=…` | Сотрудник: свой профиль; HR: любой профиль |
| `GET /api/employees`, `GET /api/hr` | Только HR |
| `GET /api/planner?id=…&hours=8` | Сотрудник: свой план; HR: план выбранного профиля |
| `POST /api/simulate` | Те же права просмотра; JSON: `employee_id`, `event_ids` (1–3 разных ID), `hours` (1–40) |
| `POST /api/complete`, `POST /api/coach` | Только сотрудник, только свой профиль |
| `POST /api/participation` | Только сотрудник; `{"paused": true}` или `false` |
| `POST /api/upload`, `POST /api/reset` | Только HR |

POST требует `application/json`; кроме входа, нужен `X-CSRF-Token`. Внешний Origin отклоняется.

## 9. Приватность и добровольность

- Сотрудник не получает список коллег, их историю или HR-сводку, включая прямые API-запросы. Публичного обмена вовлечённостью и механизма согласия на него нет: доступ коллег закрыт целиком.
- HR видит агрегаты, профили и до восьми записей в списке поддержки. Сигнал: готовность ниже 58% и доля завершений ниже 55%, без участников на паузе.
- Паузу выбирает сотрудник; XP за пропуск недельной цели не отнимаются. HR-список предназначен для предложения помощи, а не санкций.
- Сессии хранятся на сервере 8 часов, cookie — `HttpOnly; SameSite=Strict`. Выход отзывает сессию. После пяти неудачных входов с одного IP действует ограничение в пределах минутного окна.
- Сервер раздаёт только HTML/CSS/JS интерфейса, а не исходники и датасеты. По умолчанию слушает `127.0.0.1`.

## 10. Ограничения

- Нет базы данных и сохранения между перезапусками; данные, паузы и сессии находятся в памяти.
- Две локальные учётные записи; нет регистрации, управления пользователями, восстановления пароля, SSO, MFA и аудита действий.
- Встроенный HTTP-сервер предназначен для демо. Промышленное развёртывание требует HTTPS, контроля сети и корпоративной авторизации.
- Завершение — самоотчёт, реальный уровень не подтверждается тестом или наставником. Грейд автоматически не присваивается.
- Веса ранжирования заданы вручную. Нет валидации на реальных сотрудниках или доказанного улучшения HR-метрик.
- Симулятор рассчитывает выбранные шаги, а не глобально оптимальную траекторию. Нет календарного расписания, зависимостей курсов и автоматического назначения обучения.
- Импорт имеет ограниченную проверку схемы; некорректные типы и несовместимые справочники могут вызвать ошибки.
- При отсутствии требований к роли движок возвращает 100% готовности. Такой профиль нельзя считать подтверждённо готовым к повышению.
- Локальные советы шаблонные. Внешняя AI-модель требует ключа, доступа и сети; качество и стоимость зависят от конфигурации. Локальная LLM не подключена.
- Интерфейс на русском; браузерных E2E-тестов и автоматизированной проверки доступности в репозитории нет.

## 11. Deployed-версия

Подтверждённой ссылки на публично развёрнутую версию в репозитории нет. Решение проверяется локально по инструкции выше. `http://127.0.0.1:8000` — локальный адрес, не deployed-версия.
