# Career Quest

Career Quest — веб-приложение с объяснимым AI-слоем, которое строит траекторию до следующего грейда и рекомендует сотруднику 1–3 релевантные активности на основе профиля, требований роли и истории участия.

Проект создан для кейса Halyk Bank на HackAlem AI. Основной акцент сделан на качестве решения и проверяемом объяснении рекомендации. Геймификация не подменяет рекомендательную логику.

## Коротко о решении

Сотрудник видит не список разрозненных HR-событий, а ответ на три вопроса:

1. Насколько я готов к следующему грейду?
2. Какой шаг даст наибольший эффект сейчас?
3. Почему система рекомендует именно его?

Для HR доступен отдельный агрегированный экран: часто проседающие компетенции, участие в активностях, сотрудники без подходящего шага и приватный список тех, кому может потребоваться помощь.

## Главное отличие

Система не использует правило «рекомендовать самый низкий навык». Каждый кандидат оценивается одновременно по четырём группам факторов:

```text
score = 0.46 × соответствие следующему грейду
      + 0.26 × влияние на карьерную готовность
      + 0.18 × история участия
      + 0.10 × выполнимость активности
```

В интерфейсе видны все факты и вклад каждого фактора. Например, у тестового сотрудника Public Speaking ниже остальных, однако первым рекомендуется System Design: этот навык критичен для Senior, активность заметнее двигает траекторию, а сотрудник трижды пропускал похожие активности по публичным выступлениям.

## Реализованные требования

| Требование ТЗ | Реализация |
|---|---|
| Профиль и карьерная траектория | Роль, грейд, стаж, skill gap, история и процент готовности к следующему грейду |
| 1–3 рекомендации | Многофакторный ранжировщик выбирает до трёх подходящих активностей |
| Объяснение минимум по трём факторам | Для каждого шага показываются четыре фактора и полный score breakdown |
| Обновление прогресса | После завершения активности применяются `gain` и `max_level`, затем пересчитываются навыки и траектория |
| HR-view | Проседающие навыки, завершаемость, сотрудники без следующего шага и приватный watchlist |
| Проверочные профили | Интерфейс принимает дополнительные JSON/CSV-файлы по схеме стартового кита |
| Одна команда запуска | Сервер работает на стандартной библиотеке Python без установки пакетов |
| Разделение сотрудник/HR | Отдельные представления и отсутствие публичного рейтинга результативности |

## Запуск

Требуется Python 3.10 или новее.

```bash
cd career-quest
python3 server.py
```

Открыть в браузере: [http://127.0.0.1:8000](http://127.0.0.1:8000).

Другой порт:

```bash
python3 server.py --port 8080
```

Внешние зависимости, API-ключи и доступ к интернету не нужны.

## Сценарий защиты

1. Открыть профиль **Аян Серик · Backend Engineer · Middle**.
2. Показать, что самый низкий навык — Public Speaking, но рекомендация №1 развивает System Design.
3. Нажать **Почему этот шаг** и показать четыре фактора решения.
4. Нажать **Отметить выполненным**: System Design растёт, готовность к Senior пересчитывается, рекомендации обновляются.
5. Перейти в **HR-аналитику** и показать агрегированные skill gaps и участие.
6. Нажать **Загрузить датасет** и добавить проверочный профиль жюри.

Главная демонстрационная фраза:

> Мы не рекомендуем сотруднику очередной курс. Мы показываем, какой шаг приблизит его к следующему грейду, и доказываем это на данных.

## Загрузка данных

Кнопка **Загрузить датасет** принимает один или несколько файлов:

- `employees.json` — профили сотрудников;
- `events.json` — активности и развиваемые навыки;
- `skills.json` — навыки и требования по грейдам;
- `activity_history.csv` — история участия, пропусков и отказов.

Можно загрузить один JSON-объект сотрудника, массив профилей или bundle:

```json
{
  "employees": [
    {
      "employee_id": "E0028",
      "name": "Аян Серик",
      "role": "Backend Engineer",
      "grade": "Middle",
      "tenure_months": 52,
      "skills": {
        "SK_PYTHON": 3,
        "SK_SYSTEM_DESIGN": 2,
        "SK_PUBLIC_SPEAKING": 1
      }
    }
  ],
  "activity_history": []
}
```

При загрузке только профилей и истории используются встроенные справочники навыков и активностей. При загрузке полного стартового кита справочники заменяются загруженными версиями.

## Как принимается решение

Для каждого сотрудника система:

1. Определяет следующий грейд.
2. Получает требуемые уровни навыков.
3. Считает текущие разрывы и общую готовность.
4. Фильтрует активности по роли и реальному эффекту `gain/max_level`.
5. Симулирует состояние после каждой активности.
6. Учитывает завершение, пропуски и отказы от похожих форматов.
7. Ранжирует варианты и возвращает до трёх рекомендаций вместе с фактическим объяснением.

LLM в промышленной версии может переформулировать уже рассчитанные факты на русском или казахском языке, но не меняет score и уровни навыков. Это защищает систему от галлюцинаций и делает решение воспроизводимым.

## Архитектура

```text
JSON / CSV
    │
    ▼
DataStore и проверка схемы
    │
    ├── профиль и требования грейда
    ├── skill gaps
    ├── история участия
    └── правила gain / max_level
    │
    ▼
Explainable Recommendation Engine
    │
    ├── ranking score
    ├── counterfactual simulation
    └── factual explanation
    │
    ├───────────────┐
    ▼               ▼
Employee View     HR View
```

Backend использует `ThreadingHTTPServer`, поэтому параллельные запросы интерфейса не блокируют друг друга. Все расчёты выполняются локально.

## API

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/health` | Проверка готовности сервера |
| `GET` | `/api/employees` | Список доступных профилей |
| `GET` | `/api/employee?id=E0028` | Траектория и рекомендации сотрудника |
| `GET` | `/api/hr` | Агрегированный HR-срез |
| `POST` | `/api/complete` | Завершение активности и пересчёт прогресса |
| `POST` | `/api/upload` | Загрузка проверочных профилей и истории |
| `POST` | `/api/reset` | Возврат к демонстрационному набору |

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют:

- выбор критичного разрыва вместо минимального навыка;
- изменение навыка и готовности после активности;
- наличие обязательных HR-метрик.

## Приватность и ограничения

- используются только синтетические данные;
- нет публичного рейтинга сотрудников;
- HR получает агрегаты и рабочий список, а не игровую таблицу лидеров;
- рекомендация не является автоматическим кадровым решением;
- история вовлечённости не показывается другим сотрудникам;
- все числовые выводы можно восстановить из входных данных.
